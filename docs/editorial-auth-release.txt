Amira Editorial Desk authentication release
Target: supergreatwin/amira-portfolio; Supabase Amira Abdelfadil Editorial (tfarhghukyogaowjqykn).
Status: source implemented and locally verified; NOT a completed live release.

Result
Recovery links reaching the existing English/Arabic Editorial Desk URLs route to dedicated reset forms before a CMS client can consume them. A fragment added to an already open tab routes too. The reset page removes credentials from the address, validates a separate memory-only session, requires a matching password and confirmation (12+ characters), updates through Supabase Auth, and ends that local session. It asks the user to sign in again. Failed updates never finish recovery or reveal a dashboard.

The existing sign-in card adds email-code request and verification, cooldown, generic request responses, and invalid/expired-code feedback. It prohibits automatic signup and verifies email OTPs. Both password and code login check server-validated app_metadata.editorial_role for admin/editor. Editable user_metadata cannot authorize access. CMS sign-out uses local scope to preserve the independent Process session.

Preserved
Current CSS, public layout/content, editorial publishing controls, admin/editor database policies, password-reset Edge Function quotas, and every file under the-process/. No role assignment, invitation, policy, database, SMTP or deployed function was changed.
